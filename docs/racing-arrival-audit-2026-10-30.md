# 레이싱 도착·반환점 판정 조사 — 2026-10-30

아래 본문은 수정 전 조사 기록이다. 후속 구현은 마지막 절에 기록했다.

## 조사 범위

- 운영 판정과 도착 반경은 변경하지 않았다. 재현 테스트와 이 조사 기록만 추가했다.
- 당시 실주행 GPS 로그와 코스 좌표는 제공되지 않았다. 아래 결과는 합성 100m 직선/200m 왕복 코스를 실제 GPS 수신 → 기록 → 경로 매칭 → 도착 판정 → 저장 흐름으로 재생한 결과다. 사진 속 코스나 당시 원인을 확정한 결과는 아니다.
- 기존 `racingStartFixture`를 사용했다. 위치 판정·이동 판정·기록·Ghost 계산은 실제 구현이며 GPS 공급과 DOM/지도는 기존 테스트 환경이다.

## 현재 코드

- `ride-foundation.js:evaluateRouteArrival`: 단순 목적지 거리 비교만 하지는 않는다. 이전의 선택 경로 접근 여부(`approached`), 현재 경로 진행률, 현재 경로 이탈 거리 5m 이하, 현재 좌표의 도착선 뒤 반경 5m 반원 진입을 확인한다.
- 이전 좌표와 현재 좌표 사이의 결승선/구역 교차는 계산하지 않는다. 이 함수는 이전 좌표·시각을 보관하지 않으며, 전달된 `accuracy`와 `timestamp`도 판정에 사용하지 않는다.
- `app.js:advanceRacingCheckpoint`와 `observeRacingTurnaround`가 이 함수를 공유한다. 최종 완주는 왕복 반환 확인 후에만 허용된다.
- `app.js:updateActiveRacing`은 인정된 GPS 표본의 시각으로 `freezeRacingSession`을 호출한다. 결승선 통과 시각을 보간하거나 기록을 결승선에서 자르는 처리는 없다.
- `racing-foundation.js:targetProgressAtTime`은 저장된 거리·이동시간 사이를 보간한다. 도착 판정 자체를 보완하는 기능은 아니다.

정확도 100m 표본의 경우 실제 기록기가 `inaccurate`로 제외했음을 함께 검증했다. 그런데 레이싱은 완주 처리되어 저장 경로가 90m, 이동시간이 18초에서 끝나고 종료 시각은 20.4초가 되는 불일치가 재현됐다. GPS 표본의 사용 가능 여부를 기록기와 도착 판정 사이에서 맞출 필요가 있다.

정상 완주 시나리오는 5m/s로 100m 선을 20초에 통과하고 102m 표본을 20.4초에 받도록 구성했다. 현재 저장 종료 시각·이동시간은 20.4초이고 저장 경로 끝은 102m였다. 이 기록의 Ghost는 19초에 약 95m로 재생됐다. 이는 현재 저장/보간 방식의 확인이며, 실제 결승선 통과 시각이 정확하다는 증명은 아니다.

## 검증 및 남은 범위

`tests/map-place-waypoint.test.mjs`의 `Racing arrival audit:` 재현 10개와 기존 관련 검사 10개를 실행했다. 결과는 **17개 통과, 미해결 동작 3개가 기대와 불일치(TODO)**였다. TODO 표시는 테스트를 생략하지 않는다. 실제 단언이 실패하며, 이 결과를 전체 통과로 해석하면 안 된다.

기존 관련 검사는 왕복 출발/도착 좌표 중복에서 GPS 공백으로 조기 완주하지 않음, 정상 반환점의 1회 확인, 반환점 저장·재로드, 저장 Ghost 보간과 도착 구역의 기존 동작이다.

```powershell
node --test --test-name-pattern="^(Racing arrival audit:|route arrival|round Racing confirms|Racing save and reload|saved ride interpolation|updateActiveRacing does not complete|a 29-second GPS gap)" tests/map-place-waypoint.test.mjs tests/ride-foundation.test.cjs tests/racing-foundation.test.cjs
```

실제 코스에서의 재현과 오판정 여부 확인에는 당시 GPS 좌표·측정 시각·정확도 및 코스/결승선/반환점 좌표가 필요하다. 이번 조사는 현장 재주행, iPhone GPS 수신 간격 확인, 통과 판정 수정, 시간/기록 보정 또는 배포를 수행하지 않았다.

## 후속 구현 — 반경 유지, GPS 통과와 저장 기록 일치

- 도착 반경 5m와 경로 접근 조건을 유지했다. 기록기가 거부한 표본 또는 일시정지 중 표본은 레이싱 진행·최종 도착·반환 판정에 사용하지 않고 이전 통과 후보를 끊는다.
- 공통 판정기가 이전 유효 좌표·시각을 보관하고 정상 방향으로 도착선을 통과하는 선분을 검사한다. 6초 초과 공백, 비단조 시각, 정확도 50m 초과, 비정상 위치 변화는 연결하지 않는다. 레이싱에서는 기록기의 처리 속도와 위치 정확도도 이동량 검증에 사용한다.
- 통과 위치와 시각, 누적 거리·이동시간·처리 속도를 같은 비율로 보간한다. 시각과 이동시간은 밀리초로 반올림하고, 보간 여부를 `estimated`로 남긴다.
- 반환점은 통과 지점을 경로에 삽입하고 한 번만 복귀로 전환한다. 반환 확인 전 완주 차단은 유지한다.
- 완주 시 레이싱 저장본을 통과 시각에서 자르고 끝점을 삽입한다. 종료 시각·이동시간·거리·요약 통계·Ghost 표본과 최종 상대 시간 비교가 이 경계를 사용한다. 공유 일반 주행 세션은 보정하지 않는다.
- 진단 로그의 최종 도착·반환점 이벤트에 판정에 사용한 GPS 시각과 보간 결과를 남긴다.
- 기존 TODO 3개를 일반 테스트로 전환했다. 정상 102m 표본과 구역을 건너뛴 108m 표본 모두 100m/20초의 끝점을 저장하며 Ghost도 같은 경계로 재생된다. 반환점·최종 도착을 모두 건너뛴 왕복, 2km 왕복의 빠른/느린 결과, 기존 순간 튐·조기 완주 방지와 내비게이션 도착도 확인했다.
- 검증 중 기존 2km 테스트가 거리·시간만 수동 주입하고 처리 속도를 0으로 남기던 것을 발견해, 해당 픽스처에 주행 속도도 함께 설정했다. 기대 완주·비교 결과는 변경하지 않았다.

실제 iPhone 주행은 미검증이며 GPS 측정 오차 자체를 제거한 것은 아니다. 코드 변경은 아직 커밋·배포하지 않았다.
