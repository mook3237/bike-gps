RideMate 경로 선택 로직 설명서 — v8
===================================

[이 문서의 목적]
나중에 ChatGPT가 코드를 이어서 수정할 때 화면 순서를 1개로 고정하지 않도록 하기 위한 설계 규칙이다.
핵심은 "어떤 화면에서 왔는가"가 아니라 "현재 출발지와 도착지가 무엇인가"를 상태로 관리하는 것이다.

1. 가장 중요한 규칙
-------------------
A. 도착지가 확정되면 경로검색 화면을 연다.
B. 그 순간 사용자가 출발지를 따로 지정하지 않았다면 GPS 현재 위치를 자동 출발지로 사용한다.
C. 사용자가 출발지를 직접 지정했다면 그 출발지를 유지하고, 다음 도착지가 확정될 때 그 두 지점으로 경로를 조회한다.
D. 출발지만 정해졌을 때는 경로검색 화면을 열지 않는다. 도착지를 고르는 단계로 이동한다.
E. 경로검색 화면과 실제 내비게이션 화면은 서로 다른 단계다.

2. 가능한 흐름 예시
-------------------
- 목적지 검색 → 장소 선택 → 도착 → [GPS 현재 위치 → 목적지] 경로검색
- 목적지 검색 → 장소 선택 → 출발 → 다른 목적지 검색 → 도착 → [직접 지정 출발지 → 목적지] 경로검색
- 지도에서 목적지 선택 → 도착 → [GPS 현재 위치 → 지도 선택 위치] 경로검색
- 지도에서 장소 선택 → 출발 → 다시 지도에서 장소 선택 → 도착 → 경로검색
- 집 → 도착지로 사용 → GPS 현재 위치 기준 경로검색
- 회사 → 도착지로 사용 → GPS 현재 위치 기준 경로검색
- 즐겨찾기/최근검색/검색결과/지도 직접선택도 동일한 setDestination()으로 연결한다.

3. 코드의 핵심 상태
-------------------
routeState.departure
- 사용자가 직접 지정한 출발지.
- null일 수 있다.
- null이라고 해서 경로검색을 막으면 안 된다. 도착지가 정해지면 GPS 현재 위치를 대신 사용한다.

routeState.destination
- 확정된 도착지.
- 이 값이 확정되는 것이 경로검색 진입의 핵심 트리거다.

routeState.currentLocation
- navigator.geolocation으로 받은 현재 GPS 위치.
- 사용자가 출발지를 직접 지정하지 않았을 때만 자동 출발지로 사용한다.

4. 반드시 재사용할 핵심 함수
---------------------------
setDeparture(place)
- place를 출발지로 저장한다.
- 기존 도착지는 비운다.
- 경로검색을 바로 열지 않고 도착지 선택 화면으로 간다.

setDestination(place)
- place를 도착지로 저장한다.
- 직접 지정한 출발지가 있으면 그것을 사용한다.
- 직접 지정한 출발지가 없으면 getCurrentLocation()으로 GPS 현재 위치를 가져온다.
- 출발지와 도착지가 준비되면 showRouteScreen(start, destination)을 호출한다.

getCurrentLocation()
- 브라우저 GPS를 요청한다.
- 실제 앱에서는 네이티브 위치 권한/GPS 모듈로 교체할 수 있다.

5. 새 장소 선택 기능을 추가할 때
-------------------------------
앞으로 집/회사/즐겨찾기/최근 장소/카카오 검색결과/지도 롱프레스 등 새로운 진입 방법을 추가하더라도
각 기능 안에서 경로 화면을 직접 열지 않는다.

도착지로 선택했다면:
    setDestination(place)

출발지로 선택했다면:
    setDeparture(place)

이 두 함수로만 연결한다.
그래야 선택 방법이 늘어나도 경로 로직이 꼬이지 않는다.

6. 경로검색과 내비게이션의 구분
-------------------------------
경로검색 화면은 '길만 확인하는 화면'이기도 하다.
사용자가 실제로 그 출발지에 있지 않아도 임의의 출발지 A와 도착지 B를 선택하여 경로를 볼 수 있다.

경로검색 화면의 '안내 시작' 버튼을 눌렀을 때에만 실제 GPS 기반 내비게이션 화면으로 넘어간다.
현재 v8에서는 내비게이션 화면을 아직 만들지 않았으므로 '안내 시작'은 안내 메시지만 표시한다.
다음 단계에서 navigation 화면을 별도로 만든 뒤 이 버튼에 연결한다.

7. API 관련 원칙
----------------
현재 경로 화면의 지도/경로 값은 UI 데모다.
실제 연결 시 카카오/카카오모빌리티 API 응답에서 제공되는 값만 화면에 표시한다.
고도, 평지/언덕 비율, 임의의 자전거도로 퍼센트 등 API에서 받지 않은 정보는 만들어서 표시하지 않는다.

8. 절대 다시 만들면 안 되는 잘못된 조건
--------------------------------------
잘못된 방식:
    if (departure && destination) showRouteScreen(...)

이렇게만 만들면 '도착지만 고르고 현재 GPS에서 출발'하는 정상적인 사용 흐름이 막힌다.

올바른 개념:
    destination 확정
        → departure가 있으면 사용
        → 없으면 GPS 현재 위치 사용
        → 경로검색

9. 현재 화면 디자인 보존
-----------------------
경로검색 화면 디자인은 v7의 확정 디자인을 유지한다.
- 지도 + 출발/도착
- 정사각형에 가까운 경로 카드 가로 스크롤
- 경로 종류 / 예상시간 / 거리
- 고도정보 없음
- 평지/언덕 비율 없음
- 임의의 자전거도로 % 없음
- 안내 시작 버튼

이 문서를 다음 작업 때 함께 제공하면 위 상태관리 원칙을 우선하여 코드를 이어간다.
